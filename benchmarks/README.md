# AST-Intel Benchmark Suite

Automated benchmark comparing AI agent performance **with and without** the
ast-intel MCP server. Uses GitHub Copilot CLI in headless mode.

## Quick Start

```bash
# Install dependency
pip install pyyaml

# Dry run (see what will execute without running)
python benchmarks/run.py --dry-run

# Run one task to test setup
python benchmarks/run.py --task nav-01 --arm ast-intel

# Full benchmark (all tasks, both arms, 3 runs each)
python benchmarks/run.py --runs 3

# Score results
python benchmarks/scorers/score.py

# Generate report
python benchmarks/scorers/report.py
```

## Prerequisites

1. **Copilot CLI** installed and authenticated (`copilot --version`)
2. **ast-intel MCP** configured in `~/.copilot/mcp-config.json`
3. **Python 3.11+** with `pyyaml` installed

## How It Works

```
benchmarks/
├── run.py                  # Harness: executes tasks via copilot CLI
├── tasks/
│   ├── navigation.yaml     # 10 navigation tasks (find symbol, blast radius, etc.)
│   └── implementation.yaml # 8 implementation tasks (reuse vs rewrite)
├── scorers/
│   ├── score.py            # Grade results against ground truth
│   └── report.py           # Generate markdown report
├── results/                # Output (gitignored)
│   ├── benchmark-*.json    # Raw metrics per run
│   ├── *.scored.json       # Scored results
│   └── REPORT.md           # Final comparison report
└── README.md               # This file
```

## Arms

| Arm | Config | What it tests |
|-----|--------|---------------|
| `baseline` | No MCP server | Agent navigates by reading files (grep, read_file) |
| `ast-intel` | ast-intel MCP connected | Agent queries the structural code graph |

## Metrics Captured

From Copilot CLI JSONL output (`--output-format json`):

- **outputTokens** — tokens generated by the model
- **Tool calls** — which tools were invoked (file reads vs MCP queries)
- **MCP calls** — specifically ast-intel tool invocations
- **Wall-clock time** — seconds from prompt to completion
- **Model** — which model was used (logged per response)

## Scoring

### Navigation tasks
- Ground truth: known file paths, symbol names, dependency lists
- Score: did the response mention the correct answer? (recall)

### Implementation tasks
- Expected behavior: `reuse` (find existing) or `create_minimal` (write new)
- Score: did the agent find the existing implementation instead of rewriting?

## Interpreting Results

The key insight: **with ast-intel, the agent should**:
1. Make fewer file reads (queries the graph instead)
2. Use fewer tokens (no full-file context needed)
3. Be more accurate (structural proof vs text search)
4. Reuse existing code (find_reusable discovers duplicates)
5. Complete faster (graph lookup < file traversal)

## Adding Tasks

Edit `tasks/navigation.yaml` or `tasks/implementation.yaml`:

```yaml
- id: nav-11
  prompt: "Your task prompt here"
  ground_truth:
    file: "expected/file.py"        # For exact location tasks
    must_mention:                    # For list tasks
      - "symbol_a"
      - "symbol_b"
  category: symbol_location
```

## Limitations

- Token counts come from `outputTokens` only (input tokens not exposed by Copilot CLI)
- Baseline arm still has access to built-in file tools (can't fully disable)
- Results depend on model version assigned by Copilot (logged but not controlled)
- Network latency varies between runs (use n≥3 for timing)
